Use Case 01

محاولات فاشلة كثيرة ثم دخول ناجحMultiple failures followed by success

لاكتشاف Brute Force أو Password Spraying انتهى بدخول ناجح.Detect brute force or password spraying that ends in a successful login.

FieldDetails
Log SourcesWindows Security, VPN, IdP, OWA
Block 1Threshold Observed: 5–10 failed logons in 10 minutes
Block 2Log Observed: successful login for same user
Group ByUser + Source IP
ResponseCreate AIE Event/Alarm and notify SOC

تحليل التنبيهHow to Triage

  • تحقق من الـ Source IP: داخلي، خارجي، VPN، أو TOR/hosting.Check whether the source IP is internal, external, VPN, or TOR/hosting.
  • شاهد هل الفشل على حساب واحد أم عدة حسابات.See whether failures hit one account or many.
  • راجع النشاط اللاحق: mail access أو lateral movement أو admin actions.Review follow-on activity such as mail access, lateral movement, or admin actions.
Use Case 02

استخدام حساب إداري خارج النمط المعتادAdministrative account usage outside normal pattern

Behavioral: Whitelist / Statistical
Group By: User, Host, or Host Zone
Indicators: time of day, rare host, unusual source IP, privilege escalation

أفضل الممارساتBest Practices

  • أنشئ baseline أولاً قبل إطلاق monitor block.Build a baseline before enabling the monitor block.
  • استثنِ service accounts الطبيعية والـ scanners.Exclude known service accounts and scanners.
Use Case 03

انقطاع خدمة أو غياب لوق متوقعService disruption or missing expected logs

Rule Block: Log Not Observed Scheduled / Threshold Not Observed
Example: No firewall logs observed from edge device during business hours

ماذا تفحص؟What to Validate

  • تأكد أن المصدر يرسل عادةً خلال هذا الوقت.Confirm the source normally sends data during that schedule.
  • ضع schedule واقعي لتقليل false positives أثناء الصيانة.Use a realistic schedule to reduce false positives during maintenance.
