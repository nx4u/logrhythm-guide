الفحص اليومي للمنصةDaily Platform Health Check

✓
افتح Deployment Monitor وحدد أي host أو service تظهر down أو degraded.Open Deployment Monitor and identify any host or service showing down or degraded status.
✓
راجع معدل اللوقات وتأكد ما فيه هبوط مفاجئ أو زيادة غير طبيعية.Review log volume and confirm there is no sudden drop or unusual spike.
✓
تحقق من أهم المصادر الحساسة: AD, Firewall, VPN, EDR, Email, Proxy.Validate critical sources: AD, Firewall, VPN, EDR, Email, and Proxy.
✓
نفّذ بحث سريع عن AIE Events للتأكد أن correlation ما زال ينتج نتائج.Run a quick search for AIE Events to ensure correlation still produces output.
✓
افحص تنبيهات الأمس المتأخرة أو غير المعالجة.Review delayed or unhandled alarms from the previous day.

ما الأدوات التي أستخدمها؟Which tools do I use?

  • Deployment Monitor: نظرة واسعة على الحالة العامة.Deployment Monitor: broad health overview.
  • Centralized Metrics / Grafana: أداء وتوجهات واختناقات.Centralized Metrics / Grafana: performance, trends, and bottlenecks.
  • scsm.log / scarm.log / columbo.log: عند تحديد المكوّن المتأثر.scsm.log / scarm.log / columbo.log: once you identify the impacted component.
  • Web Console: تأكيد وصول البيانات وصحة البحث.Web Console: confirm data arrival and search health.

قائمة ترياج التنبيهAlarm Triage Checklist

1
اقرأ اسم القاعدة: هل التنبيه AIE أم Alarm تقليدي؟Read the rule name: is it an AIE alert or a traditional alarm?
2
افحص الـ metadata الأساسية: user, host, source IP, process, common event.Inspect key metadata: user, host, source IP, process, and common event.
3
افتح اللوق الخام وتأكد أنه يطابق التفسير المتوقع.Open the raw log and confirm it matches the expected interpretation.
4
ابحث عن سياق إضافي قبل وبعد الحدث.Search for context before and after the event.
5
صنّف الحالة: True Positive / Benign / False Positive / Needs Escalation.Classify the case: True Positive / Benign / False Positive / Needs Escalation.

أسئلة لازم تسألهاQuestions You Must Ask

  • هل هذا السلوك طبيعي لهذا المستخدم أو الجهاز؟Is this behavior normal for this user or device?
  • هل المصدر داخلي أم خارجي أم من VPN؟Is the source internal, external, or via VPN?
  • هل توجد تغييرات أو صيانة قد تفسر السلوك؟Is there a change or maintenance that explains the behavior?
  • هل التنبيه منفرد أم جزء من حملة أو تسلسل؟Is the alert isolated or part of a campaign/sequence?

قائمة Onboarding لمصدر لوق جديدNew Log Source Onboarding Checklist

✓
حدّد نوع المصدر: Windows / Syslog / Flat File / API.Identify the source type: Windows / Syslog / Flat File / API.
✓
حدّد طريقة الجمع: Push أم Pull؟ وأي System Monitor سيستقبل؟Define collection method: Push or Pull, and which System Monitor will receive it.
✓
تحقق من الشبكة والـ firewall والـ ports قبل لوم المنصة.Validate network, firewall, and ports before blaming the platform.
✓
بعد الإضافة، تحقق من Last Log Date وحجم اللوق والبحث.After onboarding, validate last log date, log volume, and searchability.

قائمة مراجعة Tuning للقواعدAIE / Alarm Tuning Review Checklist

  • هل القاعدة عامة أكثر من اللازم؟ أضف شروطاً أدق.Is the rule too broad? Add more specific conditions.
  • هل الـ threshold منخفض ويسبب alarm fatigue؟Is the threshold too low and causing alarm fatigue?
  • هل Group By مضبوط بالشكل الصحيح؟Is Group By configured correctly?
  • هل تحتاج whitelist لحسابات الخدمة أو الـ scanners؟Do you need a whitelist for service accounts or scanners?
  • هل response واضح للمحللين أم مجرد alert بدون runbook؟Is there a clear analyst response path or just an alert without a runbook?
أفضل tuning ليس فقط تقليل false positives؛ الأفضل هو رفع قيمة التنبيه بحيث يصل للمحلل مع سياق كافٍ وإجراءات محددة.The best tuning does more than reduce false positives; it increases alert value so the analyst gets enough context and a defined response path.
